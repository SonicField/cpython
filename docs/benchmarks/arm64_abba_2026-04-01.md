## Known Issues

1. **nbody crashes** under JIT on ARM64. All JIT_ON subprocess runs exit with code 1. Vanilla runs succeed (~39ms). Under investigation — likely FP codegen bug.
2. **gen_simple -26%:** Generator resume path has JIT infrastructure overhead. The JIT-compiled generator code is slower than the interpreter for simple generators.
3. **nn_module_forward -17%:** Short-running benchmark dominated by JIT startup/compilation overhead rather than execution benefit.

## Benchmark Protocol (LOCKED)

To reproduce these results:

```bash
# On devgpu004
cd ~/local/phoenix-cpython
VANILLA_PYTHON=~/local/vanilla-cpython/python \
  ./python Tools/benchmark_phoenix_full.py jit --reps=3
```

**IMPORTANT:** Use `benchmark_phoenix_full.py`, NOT `benchmark_phoenix.py`. The simpler harness has insufficient warmup — most functions never reach the auto-compilation threshold of 1000 calls, producing interpreter-vs-interpreter noise (~1.0x). The full harness uses subprocess isolation with heavy warmup, ensuring inner functions reach compilation threshold.

**Do NOT use `--compile=force`** unless specifically testing forced compilation. The default `--compile=auto` matches production behavior.

1. Always use the scripted benchmark (benchmark_phoenix_full.py), never ad-hoc harnesses
2. Verify compilation status (cinderjit.is_jit_compiled) after warmup, not from separate tests
3. Compare against vanilla CPython of the SAME version, not cross-version
